# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev          # Dev server (port 3000)
npm run generate     # Static SSG build → .output/public/
npm run lint         # ESLint
npm run lint:fix     # ESLint with auto-fix
npm run typecheck    # TypeScript type check
npm run test         # Vitest unit tests
npm run test:e2e     # Playwright e2e (Chromium, requires dev server)
npm run thumbs       # Generate WebP thumbnails from public/images/
npm run lint:data    # Validate gallery JSON data
```

Node 22+ required (see `.nvmrc`). The site deploys to GitHub Pages at `/young-portfolio/` (set in `nuxt.config.ts` `app.baseURL`).

## Architecture

**Nuxt 4 app directory layout.** All source lives under `app/` — pages, components, composables, stores, layouts, assets. Tailwind + PostCSS for styling. Static SSG via `nuxt generate` with Nitro `github-pages` preset.

### Pages & Routing

| Route | File | Notes |
|---|---|---|
| `/` | `app/pages/index.vue` | Hero, About, Domains, Featured gallery, Article snippets |
| `/gallery/[[category]]/[[event]]` | `app/pages/gallery/[[category]]/[[event]].vue` | Category: `all` / `digital` / `photography`. Optional event slug under `digital` / `photography` for per-event prerender |
| `/article` | `app/pages/article.vue` | Article listing |
| `/admin` | `app/pages/admin.vue` | CSR-only local admin panel; excluded from prerender |

- Lightbox state lives in `?image=<id>` (synced via `useGalleryImageRoute`) — query keeps it from minting separate prerendered HTML for every image.
- Event filter state lives in the **path** `/gallery/<category>/<event>` (synced via `useGalleryEventRoute`). Each event prerenders to its own HTML so social/OG crawlers see the correct hero image and JSON-LD `ImageGallery`. Event slugs are raw unicode (Wikipedia-style) — no slug dictionary.

### Data Flow

Static JSON is the source of truth. The gallery store reads from:
- `public/galleryList.json` — digital artwork
- `public/photographyList.json` — photography with EXIF, event metadata, location tags

**Pinia stores** (`app/stores/`):
- `gallery.ts` — loads both lists, exposes filtered/sorted data
- `gallerySelectors.ts` — memoized derived data (avoid re-computing in components)
- `imageViewer.ts` — lightbox open/close, current image, radial nav state
- `admin.ts` + `adminApiClient.ts` — local-only upload/edit UI

**Composables** (`app/composables/`):
- `useImagePath` — resolves image paths + WebP srcset via `_thumbs/{400w,800w}/`; handles non-ASCII via `encodeURIComponent`
- `useScrollReveal` — IntersectionObserver wiring for `.reveal` animation classes
- `useGallery*Route` — URL ↔ store state sync for image, category, event params
- `useToast` — global singleton toast

### Images

- Thumbnails at `_thumbs/400w/` and `_thumbs/800w/` generated by `npm run thumbs` (sharp script)
- Always use `useImagePath.getThumbPath(path, size)` — never construct image paths manually
- Hero image source of truth: `series: ['hero']` field in `photographyList.json`. All of `og:image`, `useSeoMeta`, JSON-LD `Person.image` derive from this tag. **To change the Hero image, edit the JSON `series` field only.**

## Design System

The visual language is Japanese editorial: **余白 (whitespace) · 間 (rhythm) · 侘寂 (wabi-sabi)**. Before adding anything, ask: can I remove it instead?

### CSS Tokens

CSS custom properties are defined in `app/assets/css/main.css` under `:root` and `.dark`. Tailwind is configured to reference these as semantic utilities:

| Token | Tailwind class | Use for |
|---|---|---|
| `--fg-2` | `text-fg-2` | Primary body text |
| `--fg-muted` | `text-fg-muted` | Captions, secondary labels |
| `--bg` | `bg-bg` | Page background |
| `--surface` | `bg-surface` | Card / section alternate bg |
| `--border` | — | Dividers (use via `var(--border)`) |
| `--accent` | `text-accent-ds` | Eyebrows, seals, hairline accents only |
| `--hairline` | — | `background: var(--hairline)` for horizontal hairlines |

Dark mode tokens are handled automatically — the `.dark` block on `<html>` re-maps all semantic vars. **Always write both light and dark variants** when using raw Tailwind stone/accent classes; when using semantic tokens (`var(--fg-2)` etc.) no dark override is needed.

### Utility Classes (`app/assets/css/main.css`)

Prefer these over raw Tailwind equivalents:

| Class | Purpose |
|---|---|
| `jp-eyebrow` | Small uppercase label with leading hairline |
| `jp-section-title` / `jp-section-ruby` | Kanji section heading + roman subtitle |
| `jp-hairline` / `jp-hairline-v` | 1px gradient-fade divider (horizontal / vertical) |
| `jp-seal` | Square rotated stamp accent (-3°) |
| `jp-body` | Mincho body text (line-height 2) |
| `jp-kana-bg` | Large decorative background kanji (low opacity, pointer-events-none) |
| `jp-frame` | Double-inset book-cover border |
| `jp-sumi-dot` | Small ink dot (replaces coloured bullet lists) |
| `reveal` / `reveal-left` / `reveal-right` / `reveal-scale` | Scroll-triggered entrance animations |
| `reveal-delay-1..5` | Staggered delay (0.1s steps) |

All `reveal` classes have `prefers-reduced-motion` fallback built in. Any custom `animate-*` you add must also include `motion-reduce:animate-none`.

### Non-Negotiables

- **Stone is the spine.** UI chrome uses `stone.*` only. `accent.*` (terracotta) appears on eyebrows, seals, and hairline focus — never as a fill colour.
- **Hairline over border.** Use `jp-hairline` or `border-stone-300/60 dark:border-stone-600/60`, not `border-2` or solid thick lines.
- **No coloured dot lists.** Use `jp-sumi-dot` or omit decoration entirely.
- **Hero is static.** No autoplay, carousel, or auto-switching. Hero strategy is one of: A (single full-bleed + greyscale + cream overlay), B (left-text / right-photo split), or C (2–4 tile collage showing both art tracks). See `.cursor/rules/design-aesthetic.mdc §11` for selection criteria.
- **Decorative text** (vertical kanji, `jp-kana-bg`) must have `aria-hidden="true"` and `pointer-events-none`.
- **Default theme is light** (`useDark({ initialValue: 'light' })`). The theme-boot inline script in `nuxt.config.ts` sets the class before Vue loads to avoid FOUC. Dark mode is optional but must remain functional — never remove `dark:*` classes.

## Key Technical Notes

- **Leaflet CSS**: Imported inside `EventMap.vue`, not in `nuxt.config.ts`. Vite 7 + Windows caused MIME errors when loading Leaflet CSS through `@fs` absolute paths from `css:[]`.
- **Pinia stores dir**: Uses default (= `./stores` relative to `app/`). Do not set `storesDirs: ['./app/stores']` — that resolves to `app/app/stores` under Nuxt 4 and silently breaks all auto-imports.
- **Payload extraction**: Disabled in dev (Windows ENOENT on `.nuxt/cache`), enabled in production via `experimental.payloadExtraction`.
- **Non-ASCII image paths**: Always go through `useImagePath` — it handles `encodeURIComponent` for Chinese characters and spaces in filenames.
- **Admin panel**: Requires the dev server running (upload API endpoint is only available in dev). It is excluded from `nuxt generate` and has `ssr: false`.
