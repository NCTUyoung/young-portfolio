# 雙館展覽動線與展籤整理

> 最新修正（使用者實際瀏覽後）：取消獨立雙館索引，避免圖片庫多一次點擊。導覽列直接進攝影展廳；舊 `/gallery` 自動轉入攝影，`digital-` 圖片分享仍轉入繪畫，query/hash 保留。首頁雙入口與展廳內分類切換繼續提供雙館導引。此決策取代下方原規格中要求獨立索引的部分，其餘系列卡、展籤及文章整理保留。

2026-10-16 使用者在全站盤點後選擇「獨立簡短雙館索引」與「攝影地圖開場、強化現有系列入場卡」，並以 implement GO 授權本輪實作。起始版本 4aba1a1；依據 `.impeccable/critique/2026-10-16T14-29-40Z__app-pages.md`。

## 既定方向與範圍

1. 首頁維持雙入口 → 作者簡介 → 收合沿革 → 署名，不恢復作品選集，不改 Hero／SEO 圖片來源。
2. `/gallery` 成為輕量雙館索引，兩個同等可見、可鍵盤操作的繪畫／攝影入口，指向既有明確分類網址。採短文字與材質差異，不複製首頁大型畫框／照片拼貼、不額外載入作品庫或地圖。保留已存篩選，不因上次類別自動跳走。
3. 明確分類、年度、活動、圖片分享連結及 browser back 繼續正常。離場的 gallery watcher 不得把索引導回類別或活動；相容分類轉址保留 query/hash。root 的已知分類圖片 ID 可交由既有分類 viewer 處理，未知 ID 不阻擋索引。
4. 攝影總覽保留 A3 地圖先行、全部圓形照片、inset、選取／平移縮放／返回狀態及鍵盤順序。只強化現有單一活動入場卡：完整比例代表照、真實系列敘事（缺少則省略）、活動名稱／位置／時間／張數及清楚 CTA；點圓圈仍只選取，點卡片才進入同一活動。不得再增加一個展品區或巢狀互動元素。
5. 統一作品顯示名稱：真實標題原樣保留；相機檔名式未命名攝影以真實活動名稱＋穩定序號顯示（沒有活動時用中性攝影作品＋序號）。原始 title、filename、ID、順序及網址不變；詳細檔案資訊保留原檔名。不杜撰作品標題或敘事。
6. 修改已盤點的次要分類、日期、展籤之字級與對比，保留暖繪冷影。擴大文章返回目錄、次要 viewer 控制項等觸控範圍，維持已良好的主要大圖工具。Viewer 的 body 捲動鎖、route query 與 focus trap 仍各由既有單一擁有者負責。
7. 文章索引每篇已刊文章只保留一個內容入口組，去除固定本週新刊、重複入口與冗長重複開場。保留真實文章／日期／未刊狀態，正文閱讀優先。文章標題仍為文章，創作手記為簡短說明。404 主行動統一為繁中回首頁／看作品。
8. 支援 light/dark、reduced motion、1440px 桌機／768px 平板／390px 手機，圖片完整比例、可讀長標題／敘事、正常 focus 與無頁面橫向溢出。不得新增依賴、自動輪播、第二個 viewer 或不相關 Wiki 變更。

## v1 實作分段、風險與退回訊號

- 雙館索引及路由護欄：新增 gallery/index.vue，維持原 gallery 頁。風險為 optional route 優先權與離場 watcher；以產出路由／SSR 索引、索引與事件往返、圖片分享檢查。索引被導走或既有分類頁消失即退回路由改動。
- 既有入場卡：selector 傳遞現有 narrative，卡片保留單一 button 與原 openSelectedEvent。風險為手機長文、照片比例與原鍵盤順序；以既有 map suite 與新卡片測試驗證。選取提前導航、返回失去視圖、鍵盤新增停點即退回互動變更。
- 展籤與文章：共用純顯示 helper＋有意義單元測試，消費端只改顯示與可讀性；文章只留一組已刊入口。風險為誤判真實標題、序號不穩、圖片 alt 不一致；原 metadata／IDs 不變，原大圖流程仍通過。
- 全面檢查與交付：先分項測試，穩定後一次完整單元／E2E、lint、typecheck 與靜態 build；一批桌／平／手機明暗截圖，最多一批確認修正。Standards／Spec 獨立審查，提交目前分支。推送及部署不在本輪 implement 指令範圍。

## 前置評估與驗收

三份獨立來源探索涵蓋路由／狀態、地圖資料／互動、展籤／viewer，修改前由 critic 挑戰 v1 的假設。已選定的兩項設計決策不再詢問；常規本機修改、測試及提交按 GO 繼續。

驗收包含：雙館 index 即使 localStorage 保存類別仍留在索引；兩入口正確；分類／事件與索引往返；地圖卡片照片與選取活動相符、無敘事時不造文；真實標題及未命名 fallback；文章已刊各一入口；新舊 viewer、地圖與後台回歸。

## v2：critic 收斂後的執行規則

- 新 index 的靜態 `/gallery` 優先權須實證，舊分類／事件／圖片同步在離開合法分類路徑時不寫 route/query；已知 `digital-`／`photography-` 根圖片連結保留 query/hash 轉交既有分類 viewer，未知 ID 留在索引。產出 `/gallery/index.html` 及其 SEO/canonical 必須是雙館索引。
- 展籤只替換空白或精確相機檔名式標題（DSC／IMG 等數字命名及編輯後綴），以及既有「攝影作品 #數字」的自動名稱。正常中文、英文字題及 digital 標題不改。序號來自完整 photographyWorks、同活動群組、日期降序與 ID 穩定排序；collection 缺少該作品時只顯示真實活動／中性名稱，不虛構序號。
- 地圖短敘事優先沿用已有 strongest_line，再用 prologue／narrative；都沒有則省略。圓圈保留範圍是既有具座標活動，不替無座標活動杜撰位置。
- 執行決策已有使用者背書，上述是安全實作收斂，不新增產品取捨或重新詢問。退回訊號與驗收依前述三段測試策略。

## 實作驗證後的收斂

實測確認原可選分類路由會優先匹配 `/gallery`，因此改為 `app/pages/gallery/[category]/[[event]].vue`，保留所有明確分類／活動網址。舊圖片分享的開啟時機等待掛載，維持既有 query 擁有者並避免 hydration 不一致。放射導覽只修正底部位置，使桌機及手機控制皆留在視窗內；手機縮圖維持實際 44px。

## 最終入口決策（取代原獨立索引驗收）

使用者試看後要求取消中間選館頁。導覽列直接進攝影；`/gallery` 僅為舊連結相容橋接，等待 client 掛載後依真實 query/hash 轉入相應分類。GitHub Pages 的建置不能把它變成寫死攝影網址的 meta refresh，否則會丟失舊圖片分享資訊。原索引畫面／SEO／停留驗收不再適用；以直接入場、雙館內部切換與靜態分享連結驗證為準。
